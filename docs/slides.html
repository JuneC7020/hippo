hippo

세션이 끊겨도 이어서 일하는 터미널 에이전트.
어제 분석한 레포를 오늘 기억하고, 실패한 테스트를 위임·리뷰까지 끝냅니다.

최민준 · MCP + Seahorse/Chroma + LangGraph · 2026.09

문제

코딩 에이전트는 매 세션이 첫날입니다

  • 컨텍스트 창은 한 번의 대화입니다. 창을 닫으면 레포 구조·컨벤션·어제 깨진 테스트가 사라집니다.
  • 한 에이전트가 계획·실행·검증을 한꺼번에 하면, 실패해도 같은 실수를 반복합니다.
  • 도구가 에이전트 코드에 붙어 있으면 교체할 때마다 프롬프트를 다시 짭니다.
한 줄 구조

기억은 프로세스 밖에, 일은 역할로 나눕니다

CLI

Typer. run / resume / memory / trace

Orchestrator

LangGraph. planner → worker → reviewer. 체크포인트 = resume

Tools

MCP filesystem · git · pytest. 화이트리스트 + --write

Memory

에피소드 / 사실 분리. Seahorse, 없으면 Chroma. MCP로 Cursor와 공유

데모 1 · 약 20초

온보딩 한 번, 도구 없이 다시 묻기

$ hippo run -w examples/sandbox "Onboard me … run the tests …"
s1:done | s2:done | s3:done | s4:done
2 failing tests (discount rounding, total+VAT). Money = integer cents.

$ hippo run --oneshot "Were any tests failing last time?"
memory backend=chroma  recalled=5
Last time, 2 tests were failing: discount rounding and total calculations.

세션 2는 새 프로세스, 도구 없음. 답은 전부 회상에서 옵니다.

데모 2 · 63초 · gpt-4o-mini

실패 테스트를 위임하고, 로그로 리뷰합니다

s1  run_pytest          → exit 1, 2 failed     APPROVE
s2  read pricing.py     → floor division       REVISE (값 없음) → APPROVE
s3  edit_file + pytest  → round(), exit 0      APPROVE
s4  run_pytest          → 5 passed             APPROVE

reviewer는 worker의 산문이 아니라 tool log(diff, exit code)를 봅니다. 그 전에는 통과한 수정을 두 번 거부했습니다.

데모 3

터미널에서 쓴 기억을 Cursor가 읽습니다

  • 같은 스토어를 MCP 서버(python -m hippo.mcp_server)로 노출.
  • hippo CLI는 이 서버를 건너뜁니다(회상은 직접 주입, Chroma 이중 오픈 방지).
  • Cursor는 다른 프로세스이므로 memory_search로 어제 에피소드를 가져옵니다.

설정: docs/cursor.md · 프로토콜 검증: scripts/demo3_mcp_share.py

설계 결정 · 왜

면접에서 물을 여섯 가지

결정왜
1에피소드 / 사실 테이블 분리검색 의도가 다름. 회상 시 에피소드 슬롯 보장
2압축 ≠ 회상압축은 한 런의 연속성, 회상은 런 사이의 선택적 정밀도
3도구는 MCP프로세스 경계. 스키마만 맞으면 서버를 갈아끼움
4planner는 목표·쓰기권한·예산읽기+pytest는 기본 도구. 예산 최소 6, 소진 시 마지막 무도구 턴
5reviewer는 별도 에이전트호출 1회 비용. 재시도 1 → 재계획 1 → 부분 결과. 무한 루프 없음
6도구는 graph state에 안 넣음체크포인트 직렬화. resume가 새 프로세스에서 MCP를 다시 연결
라이브에서 깨진 것

가설이 아니라 hippo trace에 남아 있습니다

  • anyio cancel scope — MCP 클라이언트를 전용 asyncio task에 가둠.
  • edit_file 스키마가 list로 납작해짐 — 중첩 pydantic. 모델이 키를 네 번 지어냄.
  • 경로 추측에 예산 소진 — workspace 트리 주입 + 동일 호출 반복 경고.
  • planner가 edit만 허용 — 읽기는 기본권. planner는 쓰기만 결정.
  • Seahorse flush 408 — 폴백(Chroma)을 설계한 실제 이유. 에이전트 코드 경로는 동일.
한계를 먼저

질문 나오기 전에 말할 것

  • 단일 사용자·단일 머신. SQLite → Postgres 전환 지점만 명시.
  • reviewer는 테스트가 통과했는가이지 수정이 옳은가가 아님. 데모 2의 round()는 banker's rounding.
  • 회상 품질은 아직 정량 평가 없음. dense top-k + 에피소드 몫.
  • 프롬프트 인젝션 방어는 도구 화이트리스트와 --write 게이트.
